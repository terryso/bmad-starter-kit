# Story 完成定义 (Definition of Done)

**版本**: 1.0
**生效日期**: 2026-01-04
**适用范围**: 所有开发 Story

本文档定义了一个 Story 被视为"完成"所需满足的所有条件。基于 Epic 5 回顾中的经验教训制定。

---

## 核心原则

> **"测试与真实使用场景不能脱节"** — Epic 5 回顾总结

单元测试通过 ≠ Story 完成。必须验证功能在真实环境中的可用性。

---

## Story 完成检查清单

### 1. 代码质量 ✅

- [ ] 代码符合项目规范 (参考 `docs/project-context.md`)
- [ ] 代码通过 Linter 检查
- [ ] 没有 console.log 或调试代码残留
- [ ] 没有 TODO 或 FIXME 注释 (除非已记录在技术债务中)
- [ ] 适当的错误处理和边界情况处理

### 2. 单元测试 ✅

- [ ] 所有新增代码有对应的单元测试
- [ ] 测试覆盖率不低于 80%
- [ ] 所有测试通过 (`pnpm test --run`)
- [ ] 测试 mock 结构正确且最新
- [ ] 关键逻辑有边界测试

### 3. 集成测试 / API 测试 ✅

- [ ] API 端点有对应的集成测试
- [ ] 测试真实 API 调用 (或 MSW mock)
- [ ] 测试认证/授权逻辑 (如适用)
- [ ] 测试错误响应 (404, 400, 500 等)

### 4. E2E 测试 / 手工验收 🆕 **关键改进**

**E2E 测试优先，手工验收作为补充**

- [ ] **核心用户流程有 E2E 测试覆盖** (推荐使用 Playwright)
- [ ] **或通过 Chrome 插件进行完整的手工验收**
- [ ] **涉及用户交互的功能必须手工验证**
- [ ] **外部可观测行为必须验证** (如二维码可扫码、下载文件正确)

#### 手工验收检查清单

使用 Chrome 插件验收时，验证以下项目：

**UI/UX 验证:**
- [ ] 页面在桌面端显示正常
- [ ] 页面在移动端响应式适配
- [ ] 深色模式显示正常
- [ ] 加载状态、错误状态、空状态都有展示

**功能验证:**
- [ ] 表单提交成功并有反馈
- [ ] 按钮点击有正确响应
- [ ] 文件上传/下载功能正常
- [ ] 二维码/条码可被扫描识别
- [ ] 复制链接功能正常
- [ ] Toast/通知显示正确

**数据验证:**
- [ ] 数据正确保存到数据库
- [ ] 列表页显示最新数据
- [ ] 详情页显示完整数据
- [ ] 分页/筛选功能正常

### 5. 文档更新 ✅

- [ ] Story 文档状态更新为 `done`
- [ ] `sprint-status.yaml` 更新
- [ ] 技术债务已记录到 Story 文档 (如有)
- [ ] 架构变更已记录 (如有)

## E2E 测试指南

### 需要编写 E2E 测试的场景

| 场景类型 | 示例 | 测试方式 |
|----------|------|----------|
| 表单交互 | 登录、注册、上传 | Playwright |
| 文件操作 | 下载、二维码 | 手工验收优先 |
| 外部集成 | 第三方支付、短信 | 手工验收 |
| 视觉验证 | UI 布局、响应式 | Playwright + 截图 |

### 手工验收流程

1. **启动应用**
   ```bash
   pnpm dev:all
   ```

2. **打开 Chrome 浏览器插件**
   - 导航到需要测试的功能
   - 执行验收检查清单

3. **记录问题**
   - 发现问题立即记录到 Story 文档
   - 截图/录屏保存证据
   - 修复后重新验收

4. **验收通过**
   - 所有检查项通过
   - 更新 Story 状态为 `review`
   - 提交 Code Review

## 不同类型 Story 的特殊要求

### 前端 UI Story

- [ ] 组件单元测试 (React Testing Library)
- [ ] 可访问性测试 (a11y)
- [ ] **手工验收: 多设备/多浏览器验证**
- [ ] **手工验收: 深色模式验证**

### 后端 API Story

- [ ] API 单元测试 (Jest)
- [ ] API 集成测试
- [ ] 错误场景测试
- [ ] **手工验收: Postman/curl 验证真实调用**

### 数据库 Story

- [ ] Migration 测试
- [ ] 数据一致性测试
- [ ] **手工验收: 数据迁移后验证现有数据**

### 集成 Story (前后端)

- [ ] 端到端流程测试
- [ ] **手工验收: 完整用户旅程验证**

## Story 状态流转

```
ready-for-dev → in-progress → dev-done → 验收阶段 → review → done
                    ↑           ↓
                    └───────────┘
                  (验收不通过修复)
```

**验收阶段定义 (新增)**:
- 开发者完成开发后，**必须先进行自我验收**
- 自我验收通过后，标记为 `review`
- Code Review 期间，Reviewer 进行**二次验收**
