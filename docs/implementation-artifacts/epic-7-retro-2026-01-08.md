## 遇到的挑战

### 1. shadcn/ui Select 组件限制
**问题**: Select 组件不接受空字符串作为有效值
**表现**: 用户列表页面完全空白
**根本原因**: 使用 `roleFilter: ''` 作为初始值
**解决方案**: 改用 `'ALL'` 作为"全部"选项的值
**教训**: 需要了解 UI 库组件的约束和限制

### 2. Jest 模块解析配置
**问题**: shared 包模块无法解析
**错误**: `Cannot find module './types/index.js'` 和 `SyntaxError`
**根本原因**: moduleNameMapper 指向 dist 目录但需要 src 目录
**解决方案**: 更新 jest.config.js 指向 src，移除 .js 扩展名
**教训**: Monorepo 共享包需要特别注意 Jest 配置

### 3. 代码审查发现问题趋势
| Story | 高优先级 | 中优先级 | 低优先级 |
|-------|---------|---------|---------|
| 7.1 | 0 | 0 | 0 |
| 7.2 | 4 | 1 | 2 |
| 7.3 | 0 | 0 | 0 |

**观察**: Story 7.2 是新功能，问题较多；7.3 复用模式后质量提升

### 4. 分页切换时的闪烁问题
**问题**: 切换页面时短暂显示"暂无用户"
**用户反馈**: "不应该翻页切换任何状态，保持原来的数据显示不动"
**解决方案**: 使用 `placeholderData: (previousData) => previousData`
**教训**: React Query 的 placeholderData 可以显著改善用户体验

## 核心洞察

### 1. 共享常量模式的价值

Epic 7 首次创建 `packages/shared/src/constants/` 目录，用于存放前后端共享的常量。

**价值**:
- 单一数据源，避免魔法数字
- 前后端行为一致
- TypeScript 类型安全
- 易于维护和修改

**建议**: 继续扩展共享常量，考虑添加 API 路径、状态码等。

### 2. 代码审查作为质量守门员

Story 7.2 的代码审查发现了 7 个问题，其中 4 个是 HIGH 优先级：

1. lastActiveAt 字段未实现 - 通过更新 AC 标记为延迟实现
2. 硬编码的分页大小 - 创建共享常量解决
3. 搜索无防抖处理 - 添加 300ms 防抖
4. Controller 硬编码用户 ID - 使用 @CurrentUser() 装饰器

**观察**: 这些问题在功能实现时容易忽略，但代码审查能系统性地发现。

**建议**: 继续坚持严格的代码审查标准。

### 3. 用户体验优化来自用户反馈

Story 7.2 的两个关键优化来自用户反馈：

1. **分页闪烁问题**: 用户报告切换页面时显示"暂无用户"
   - 解决方案: `placeholderData: (previousData) => previousData`

2. **分页组件显示所有页码**: 用户报告"有多少页就所有页面都在UI上展示了"
   - 解决方案: 智能分页算法，省略号显示

**洞察**: 真实用户使用场景能发现开发时忽略的问题。

### 4. Admin 模块的复用价值

Story 7.2 创建的 Admin 模块为 Story 7.3 提供了：
- 模块结构 (admin.module.ts, admin.controller.ts, admin.service.ts)
- 权限保护模式 (JwtAuthGuard + RolesGuard + @Roles(Role.ADMIN))
- 并行查询模式 (Promise.all)
- 统一响应格式

Story 7.3 只需添加 getStats 方法和相关路由，大幅提高开发效率。
